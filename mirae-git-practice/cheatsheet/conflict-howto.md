# 충돌(Conflict) 해결 3단계

> 충돌은 **고장이 아니라 안전장치**입니다.
> Git이 데이터를 잃은 게 아니라, "둘 중 어느 쪽이 맞나요?"라는 **결정을 사람에게 넘긴 것**입니다.
> 양쪽 내용 모두 파일 안에 안전하게 들어 있습니다.

---

## 언제 생기나

두 사람이 **같은 파일의 같은 줄**을 다르게 고쳤을 때 생깁니다.
혼자 작업할 때도 **GitHub 웹에서 고친 것**과 **내 컴퓨터에서 고친 것**이 부딪히면 똑같이 생깁니다.

---

## 1단계 — 원격 변경을 먼저 받아옵니다

`push`가 이렇게 거절되면:

```
! [rejected] main -> main (non-fast-forward)
```

당황하지 말고 받아옵니다.

```bash
git pull --no-rebase origin main
```

```
CONFLICT (content): Merge conflict in CONFLICT.md
```

이 메시지가 나오면 **정상**입니다. 다음 단계로 갑니다.

---

## 2단계 — 마커 3줄을 지우고, 남길 내용만 남깁니다

충돌한 파일을 편집기로 열면 이런 표시가 있습니다.

```
<<<<<<< HEAD          ← 이 줄 삭제
내가 고친 내용          ← 남길지 결정
=======               ← 이 줄 삭제
상대가 고친 내용        ← 남길지 결정
>>>>>>> main          ← 이 줄 삭제
```

- **위쪽(`<<<<<<< HEAD` 아래)** = 내가 고친 것
- **아래쪽(`=======` 아래)** = 원격에 있던 것

여러분이 할 일은 **마커 세 줄을 지우고 최종적으로 남길 내용만 남기는 것**뿐입니다.
양쪽을 다 남기고 싶으면 둘 다 남겨도 됩니다.

**정리 후 예시**

```
내가 고친 내용
```

파일 안에 `<<<<<<<`, `=======`, `>>>>>>>` 가 **하나도 남아 있지 않은지** 꼭 확인하세요.

---

## 3단계 — 해결했다고 알려주고 올립니다

```bash
git add CONFLICT.md
git commit -m "fix: 충돌 해결"
git push origin main
```

```bash
git status
```

`nothing to commit, working tree clean` 이 나오고 GitHub에 최종 내용이 보이면 성공입니다.

## 안전하게 연습해 보기

[`../sandbox/CONFLICT.md`](../sandbox/CONFLICT.md) 파일이 연습용으로 준비돼 있습니다.
이 파일에서 일부러 충돌을 만들어 보면, 실무에서 처음 만났을 때 당황하지 않습니다.

1. **GitHub 웹**에서 `sandbox/CONFLICT.md`를 열고 연필(✏️) 아이콘 → 표시된 줄을 **A**로 고쳐 커밋
2. **내 컴퓨터**에서는 `pull` 하지 않은 채 같은 줄을 **B**로 고치고 커밋
3. `git push` → **rejected** 확인
4. 위의 1~3단계로 해결

## 자주 하는 질문

**Q. 충돌이 나면 제가 뭘 잘못한 건가요?**
아닙니다. 여러 사람이 같은 파일을 고치면 자연스럽게 생기는 일입니다. 실무에서는 매주 일어납니다.

**Q. 어느 쪽을 남겨야 하나요?**
Git은 모릅니다. **내용을 아는 사람**이 정해야 합니다. 판단이 안 서면 상대에게 물어보는 게 정답입니다.

**Q. 다 지워버렸는데 되돌릴 수 있나요?**
아직 커밋하지 않았다면 `git restore 파일명` 으로 충돌 상태로 되돌아갑니다.
